# Sweetmeter 2026.9.3 firmware acceptance

Firmware source: `e727df19f1b6e7556d70e78dc532da3f4dc42425`.
Accepted build: [Test push run 35502599344](https://github.com/luvxinc/Sweetmeter/actions/runs/35502599344).
Firmware SHA-256: `e9fddce4e0bb2ef93541b1cf42683067f215a63232f325b0eb74317dde354629`.

Test hardware: one ELECROW CrowPanel 2.13(E), PCB V1.2, JD79661,
ESP32-S3, powered over USB. Host: Apple Silicon Mac, macOS 26.6.2.
The existing unit's complete 8 MB flash was backed up privately before USB
migration. Pairing records, account data and raw logs are not release assets.

This record covers firmware acceptance before first publication. Additional
desktop updater or owner observations belong in the release notes.

## Automated checks

The push and pull-request checks passed Python tests, portable C++ state tests,
firmware compilation and native packaging/self-tests for macOS arm64, macOS
Intel, Windows x64 and Linux x64. Linux ARM64 source tests and firmware builds
ran in the dedicated disposable VM on the owner's Mac mini.

## Physical acceptance

The baseline is the genuine 2026.9.2 CI firmware. Normal OTA targets the exact
2026.9.3 CI image above. Deliberately failing 2026.9.4/2026.9.5 images are private
acceptance fixtures from the same source; they are not future public releases.

| Case | Result |
| --- | --- |
| Baseline BLE, clock synchronization, frame CRC acknowledgement | Passed on baseline 2026.9.2 and production 2026.9.3 |
| Invalid signature | Rejected; previous firmware booted after EN reset |
| Cancel after at least 65,536 acknowledged bytes | Passed; previous firmware remained bootable |
| Disconnect after at least 262,144 acknowledged bytes | Passed; previous firmware remained bootable |
| Corrupted full image | Digest rejected; previous firmware booted after EN reset |
| Failed startup health check | Passed; confirmed rollback to healthy 2026.9.2 with host selection preserved |
| Restart before startup confirmation | Passed; confirmed rollback to healthy 2026.9.2 with host selection preserved |
| Exact production image OTA | Passed; running 2026.9.3, healthy boot, durable success result and preserved host |
| Final display and physical button inspection | Driver/frame ACK passed; owner inspection pending |

One early rollback-fixture transfer disconnected before commit. It was not
counted as a rollback test. The complete retry passed; no partial candidate was
selected for boot. A full transfer/check took about seven minutes on this setup;
BLE adapters, interference and host power state can change that time.

Legacy QM3 migration required forgetting only this meter's old macOS Bluetooth
pairing to discard cached GATT characteristics, then reconnecting. The selected
computer stored on the meter was preserved. The private acceptance runner used
service-filtered discovery of the exact meter before connecting, matching the
production companion's discovery approach.

## Limits

An ACK is not optical inspection. Windows/Linux physical Bluetooth adapters,
macOS Intel physical Bluetooth, real removal/restoration of power, battery
charging, charge estimation and battery runtime have not been accepted by this
record. The stock board cannot report a meaningful battery percentage without
an added gauge. macOS packages are ad-hoc signed, not Developer ID notarized;
Windows packages do not have Authenticode signing.
